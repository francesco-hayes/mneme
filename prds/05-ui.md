# PRD 05: UI

Covers build step 5, MVP features 3 (side-by-side manual notes) and 4 (recent notes list), and the Design and UI section. Issues: 015–020.

## Problem

The user needs to start a meeting in one click, type notes with nothing in the way, and find the notes and transcript afterwards.

## Design principles

- **Notes first.** The editor is the largest thing on screen in every meeting view.
- **Always clear when it is listening.** Recording state is visible from anywhere in the app.
- **Feels like a Mac app.** System font, native window chrome, light and dark mode following the system, system accent color.
- **Quiet during meetings.** No live transcript, no popups, no badges while recording.

## Non-goals

- Sidebar navigation, search, Live Preview-style rendering, a real visual identity. All later.
- Enhanced notes, templates, Q&A.

## Screens

| Screen | Requirements |
| --- | --- |
| First run | Shown until one model is installed. Model picker with size and speed notes, download progress, checksum check, then microphone and system audio permission prompts. Recommends headphones. |
| Home | Meetings newest first with title, date and duration. New meeting button, disabled with an explanation until a model is installed. Clicking a meeting opens it full window. Each row ends in a ⋯ menu with View and Delete; Delete asks first and moves the meeting to the Trash. Interrupted meetings are marked. Empty state. |
| Meeting, live | Back button, title field with a date-time default, editor, recording bar with timer and Stop. No transcript. Notes autosave. |
| Meeting, after | Same layout, notes full width. Transcript button shows a ready state with the line count. Transcript opens in a collapsible side pane, closed by default, with two speaker styles. Show in Finder. |
| Settings | Installed models with size and delete, download more with progress, default model, global shortcut (unset by default). No language setting: v1 is English only. |

## Core flow

1. **Start.** New meeting starts recording right away with a date-time title and puts the cursor in the editor. No title prompt.
2. **During.** Notes are typed while transcription runs hidden. The recording bar stays visible, including on Home and Settings.
3. **Stop.** The notes keep the full window. The Transcript button shows the transcript is ready; the pane stays closed.
4. **Later.** Home lists the meeting; opening it allows reading, editing and Show in Finder.

## Editor

- CodeMirror 6 with Markdown highlighting: markers visible but dimmed, headings and bold styled in place. The text in the editor is exactly the text on disk.
- Autosave shortly after typing stops, and on leaving the view. Saves go to `api.saveNotes`; the backend handles the timeline.
- The title is editable during and after the meeting.

## API contract

The UI talks to the backend only through this module. A mock implements it with in-memory data; PRD 06 implements it with Tauri commands and events.

```ts
type MeetingStatus = 'recording' | 'complete' | 'interrupted';
type Permission = 'granted' | 'denied' | 'undetermined';

interface MeetingSummary { id: string; title: string; startedAt: string; durationSecs: number | null; status: MeetingStatus }
interface Meeting extends MeetingSummary { notes: string; transcriptLineCount: number; folderPath: string }
interface TranscriptLine { t: string; speaker: 'Me' | 'Them'; text: string }
interface ModelInfo { id: string; name: string; sizeBytes: number; note: string; englishOnly: boolean; installed: boolean }
interface DownloadProgress { modelId: string; receivedBytes: number; totalBytes: number; state: 'downloading' | 'verifying' | 'done' | 'cancelled' | 'error'; error?: string }
interface Settings { defaultModelId: string | null; language: string; globalShortcut: string | null; spellcheck: boolean; microphoneId: string | null }
interface RecordingState { status: 'idle' | 'recording' | 'stopping'; meetingId: string | null; elapsedSecs: number; modelId: string | null; warning: string | null; starting: boolean }
interface Permissions { microphone: Permission; systemAudio: Permission }
interface Microphone { id: string; name: string; isDefault: boolean }
interface RecordingError { action: 'start' | 'stop'; message: string }

interface Api {
  listMeetings(): Promise<MeetingSummary[]>;
  getMeeting(id: string): Promise<Meeting>;
  getTranscript(id: string): Promise<TranscriptLine[]>;
  startMeeting(): Promise<Meeting>;
  stopMeeting(): Promise<Meeting>;
  saveNotes(id: string, notes: string): Promise<void>;
  renameMeeting(id: string, title: string): Promise<MeetingSummary>;
  showInFinder(id: string): Promise<void>;
  deleteMeeting(id: string): Promise<void>;
  getRecordingState(): Promise<RecordingState>;
  onRecordingState(cb: (s: RecordingState) => void): () => void;
  onRecordingError(cb: (e: RecordingError) => void): () => void;
  onOpenMeeting(cb: (meetingId: string) => void): () => void;
  listModels(): Promise<ModelInfo[]>;
  downloadModel(id: string): Promise<void>;
  cancelDownload(id: string): Promise<void>;
  deleteModel(id: string): Promise<void>;
  onDownloadProgress(cb: (p: DownloadProgress) => void): () => void;
  getSettings(): Promise<Settings>;
  updateSettings(patch: Partial<Settings>): Promise<Settings>;
  listMicrophones(): Promise<Microphone[]>;
  getPermissions(): Promise<Permissions>;
  requestPermission(kind: 'microphone' | 'systemAudio'): Promise<Permission>;
}
```

A change to this contract is made in the types file first and noted in the issue that needed it.

What the fields added by [issue 028](../issues/028-spellcheck-and-recording-fixes.md) mean:

- `Settings.spellcheck`: the notes editor marks misspelled words. Off by default. Autocorrect stays off either way.
- `RecordingState.modelId`: the model the recording uses, from the moment it starts loading (while `status` is still `idle` and `meetingId` null) until the meeting is closed. Null otherwise. That model cannot be deleted.
- `RecordingState.warning`: one sentence saying a channel is not being recorded (for example system audio refused, so the meeting has the microphone only), or null. It stays for the rest of the meeting.
- `RecordingState.starting` (issue 031): a start is loading its model, from the menu bar, the shortcut or the window. Only with `status` `idle` and `meetingId` null; `modelId` names the model. A second start is refused meanwhile, so the window disables its own. An idle state without it still means no meeting is open (the last one is closed on disk).
- `deleteMeeting` (issue 033): moves the meeting's folder, with its notes and transcript, to the Trash, where Finder's Put Back restores it. Refused while that meeting is being recorded or stopped.
- `onOpenMeeting`: the backend asks the window to show a meeting, the live one, when Open Mneme is chosen from the menu bar during a recording.
- `Settings.microphoneId` and `listMicrophones` (issue 032): the input device that records Me, by its Core Audio id, or null for the system default. `listMicrophones` gives the devices connected now, with `isDefault` on the system default. A chosen device that is not connected is not an error: a meeting records the default until it is plugged in, then moves to it. A change applies from the next meeting.
